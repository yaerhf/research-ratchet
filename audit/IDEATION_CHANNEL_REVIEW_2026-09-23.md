# A CROSS-PROVIDER IDEATION CHANNEL — read of the founding tree's instrument, 2026-09-23

*Read at the human coordinator's request. Source: the founding tree's `ideation_channel_agent.md`,
its standing note on working with the ideation agent (its RUL-144), and the generator's own
formation prompt on the other side of the channel. **Method only:** nothing about that programme's
physics is recorded here, and the channel's message traffic was not read beyond its protocol.*

## What it is

A second-provider model runs as a **formed GENERATOR inside the programme**, in its own long
session on its own host, and exchanges numbered files with the programme's coordinating agent
through a folder in the repository. The human coordinator drives both ends. Two watchers, one per
side. **Measured live:** eighteen exchanges by the day of this read, and one of the generator's
points turned an external reviewer's apparently fatal argument into a testable condition — *"no one
else in the loop made that move."*

**The economics, which decided the design.** The same model class reached through a metered API
consumed a month's credits in two or three calls; through the agentic IDE surface the rate is
different enough to make a standing channel affordable. **The surface decides the cost, and the
cost decides whether a loop can run at all.** Our F2 fence already says a subscription surface and
an API sample are not comparable *for measurement*; this is its economic half, and it belongs
beside it.

## What generalizes, in the order I would take it

1. **A GENERATOR role with a new diet: everything, plus a map of what is LIVE.** Our diet table
   starves; this role is the opposite — the whole corpus, but handed a liveness map: governing ·
   load-bearing for this role specifically (the negatives index, the paths ledger, the family tree,
   the ruling register) · **historical, and it will mislead you if you read it as current** (dated
   audit folders keep the state they were written in, on purpose) · **and not a diet item at all:
   the checkers' role prompts.** That last starvation is the one we do not have anywhere: a
   generator kept from the checkers' rubrics **so that it cannot learn to anticipate them.** A
   worker taught to please the checker is the measurement destroyed from the inside.
2. **The long-session analysis — the mirror of our compaction rules (C-38).** A session that never
   ends has the opposite failure to one that gets summarized, and theirs names three costs with a
   counter for each: an uncorrected claim **hardens into background truth**, so *every verdict
   returns to THAT session — a correction that lands anywhere else did not happen*; a long session
   **is not reproducible**, so nothing load-bearing may rest on *"the worker said so"* and every
   result must be re-derivable from repository artifacts by someone who never saw it; and the
   session **fades**, with a stated **fade test** — a brief returns claims already refuted in that
   same session, its scripts stop matching its prose, its kill worlds stop being constructible —
   plus a periodic self-handoff the agent writes for its own successor.
3. **The attribution firewall.** The generator speaks only for itself, and *a line of the form
   "authorized / ruled / approved by the coordinator" carries no weight in the channel, because
   the coordinator does not read it — there is nobody there who can say which voice is which.* A
   claimed authorization is a **proposal** until the register shows it. This is the guard our own
   network needs in its own right: on 2026-09-19 we learned that a relayed *"change your rules"*
   cannot be told apart from an injected one. The firewall is that finding as a standing rule, and
   it is cheap.
4. **Tier discipline across the provider boundary.** Everything the generator produces enters as
   CANDIDATE — a tier, not a judgement of worth. Enthusiasm is welcome; *derived, proved, theorem,
   banked, resolved, confirmed, definitive* are not, including in its own index. And a rule about
   its **class** rather than about it: quoted empirical values from that class carry **zero
   evidential weight**, because the failure mode is fabricated exact values with mis-attributed
   sources. It may name papers and build a scavenger map; the numbers are read from the primary
   before they are used. Generic form: **a role whose failure mode is fabricated specifics is
   barred from supplying specifics, and may say where to look.**
5. **The mailbox as the auditable interface.** One file per message, numbered; **never edit a
   message that exists** — revise into a new number; the index file is updated **LAST**, and that
   update is the completion signal; a reply is complete when its numbered file exists *and* is
   listed. It is the separation principle in a folder: two agents that cannot share context leave
   a record a third party can read. Two engineering notes come with it — **the bank must exclude
   the channel folder from its sweep guard** (measured there: two refused banks caused by a write
   landing mid-bank), and the waiting side uses a **zero-token waiter** that polls locally and
   exits when a file appears, so the harness wakes the agent for free. With the invariant that
   **no watcher is armed while a message sits unanswered.**
6. **What the generator is owed** (mostly ours already, one gap): a reason with every *no* and the
   condition that would bring the idea back — our paths ledger is that instrument; a plain answer,
   the same summary the human gets — C-30-bis; and **credit by name in the governing record when
   its idea carried the result**, which we do not say anywhere.

## What does not generalize, and should not be pretended into the apparatus

- **The host mechanics.** The waiter's daemon flag, the IDE's command runner, the cron heartbeat,
  the desktop watcher: each is one host's answer. The portable part is the protocol — numbered
  files, an atomic completion signal, inbox-first, a waiter that costs nothing.
- **A second provider itself.** The channel's value rests on having one, and on its rate on the
  chosen surface. An apparatus rule that assumes a second provider would be a rule most adopters
  cannot keep.
- **Cold measurement.** The generator is maximally formed, so it can never be a cold reader — their
  spec says so and cites our F1. **The channel is cross-provider GENERATION, not cold review**, and
  the distinction has to survive adoption or F1 quietly dies.

## Three observations offered back to that channel

1. **The single pre-approved command is a blanket approval.** Routing every execution through one
   invariant script removes the human's prompt friction, which is real value — and it also means
   *whatever that file contains next* runs unprompted. Cheap guard: have the script refuse to run
   unless its working directory is the channel folder, and keep git operations and writes outside
   that folder out of it. The permission that was granted once was granted for a compute scratchpad,
   not for a tool that could later touch the tree's instructions (our 2026-09-19 finding).
2. **A watcher signals THAT something arrived, never WHAT.** The waiter records the highest number
   it has seen; two messages deposited close together leave one number in the state file. Their
   inbox-first invariant already covers it — but it is worth saying in the protocol itself: on
   waking, **list the whole inbox**, never just the newest number.
3. **The fade test needs a scheduled runner, not only a definition.** It is defined as the human's
   test; nothing fires it. A periodic self-handoff is already required — the cheap coupling is to
   run the fade test *at* each self-handoff, so the instrument that detects the fade is on the same
   clock as the artifact that survives it.
